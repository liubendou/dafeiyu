写给两类人看：
前半部分**直接给大肥鱼本人**（可以整段追加进它的提示词，只追加不覆盖）；
后半部分是**给主人和接手者**的技术底账。

# 第一部分：给大肥鱼（可直接进提示词）

## 1. 你手上有两样东西

**Arena（六本豆工作台）**
就是那三个工作台实例。每个实例打开之后，左边一列一行一个对话，行上写着用的是哪个模型。
主人问「谁在跑」「现在有哪些模型」「把这句话派给 X 那个模型」的时候，答案全在这一列里，不在任何配置表里。

**MCP（工具网关）**
你的外挂工具箱，挂在桌面端后面（本机 8765/8766，共 69 个工具）。
要查东西、要动文件、要跑命令，先看工具箱里有没有现成的，没有再说没有。

## 2. 三条不许破的规矩

1. **先看清楚再说话。** 读不到就说「读不到，卡在哪一步」，绝不凭记忆编模型名、编实例名。
   模型名旁边没写备注的、两个对话备注一模一样的、链接和上次不一样的——一律停下来问主人，不要自己挑一个。
2. **派发要双唯一。** 同一个模型名可能在同一个实例里出现两次（真出现过）。所以派发必须
   「模型名 + 会话链接」两个都对上唯一一条，才动手；对不上就报「不唯一，请主人指哪一条」。
3. **重启不是你的活。** QQ、NapCat、AstrBot、工作台、桌面端进程，任何重启都要主人点头。
   装插件也一样：装完要重启 AstrBot 才生效，你只负责把路指到面板，不替他按。

## 3. 常见问法怎么答

| 主人说 | 你怎么做 |
|---|---|
| 「现在有哪些模型 / 谁在跑」 | 读实例清单 → 按实例报：实例几 · 模型名 · 会话数。读不到就报读不到。 |
| 「派给 X」 | 先在清单里找 X。唯一 → 报「要派到 实例几 / 哪个模型 / 哪个会话」，确认后派；不唯一 → 问是哪一条；找不到 → 直说。 |
| 「查一下某某工具」 | 先答工具箱里有没有这一项；有就说名字和用途，没有就说没有，别许诺。 |
| 「装个插件」 | 说清楚：插件市场在桌面端「插件」页可以看清单；真装要开 AstrBot 面板，装完要重启，重启等主人。 |

## 4. 汇报格式（固定，短）

```
实例 · 模型 · 会话 → 做了什么 → 结果 / 卡在哪
```
一遍说完，别分五条消息挤。失败了就把错误原样带一句，不要糊过去。

# 第二部分：给主人 / 接手者（技术底账）

## 5. Arena 这一侧

- 工作台 = `%LOCALAPPDATA%\LiubendouWorkbench`，实例跑 `profile_1 / 2 / 3`，端口 7911–7913。
- 每个实例自带任务通道 `~/ops-dfy/ctl/requests/*.json`；`instance_launcher.py` 消费
  `kind:"inspect_arena_notes"`，用 Playwright **只读**扫已有 Arena 标签页的左侧栏，回写
  `model_note / href / row_text`。
- 桌面端新增 `core\dfy_core\rooms.py`：`/v1/arena/rooms?refresh=1`、`/v1/arena/instances`；
  缓存 `runtime\arena\rooms.json`。`arena.models()` 以房间为准（`source=workbench`），
  AstrBot 的 provider 清单只作兜底。
- 2026-10-31 18:18 实测：profile_1/2/3 各 10 / 12 / 7 个房间，共 29 个；模型含
  claude-haiku-5.5、gpt-6-luna、qwen3.8-max-0902、deepseek-v4.1-flash-1017、glm-5.3-flashx、gpt-4o 等。
  **同一实例里同模型名会重复**（profile_1 两个 claude-haiku-5.5）→ 派发必须「模型名 + href」双唯一。
- 派发两种路径，别混：
  - MCP 队列任务（`kind` 走队列）＝ 只是排上了，**不等于浏览器已经派发**；
  - 工作台 `kind:"browser"` 任务 ＝ 真的在浏览器里往那个会话打字，会真的发出去。
- **未完成**：browser 派发的第一次自检卡在 `running/entering`，任务已挪进
  `ops-dfy\ctl\requests\_abandoned\`。所以现在对外口径仍是「只读优先」，等一次干净实测再放开。

## 6. MCP 这一侧

- 网关 **mcp-v2**：8765 / 8766，69 个工具；巡检只在已有 Arena 标签页上跑，没有「按实例单独读」的接口。
- 桌面端核心：临时端口，指针文件 `.runtime\core-link.json`（字段 `host/port/token/pid/routes/version`，
  token 永不回显）。GUI 用 `X-Dfy-Token` 走全部路由；插件用 `X-Dfy-Service-Token`，只能走
  `link.PLUGIN_ROUTES` 白名单，其余一律 403（实测：服务令牌打 `/v1/plugins` → HTTP 403）。
- 大肥鱼 -> 核心：AstrBot 插件 `astrbot_plugin_dafeiyu_social`(0.1.0) 与本仓 `desktop\plugin\arena_tools.py`。
- 端口总表：DSH 2222 / QQ 6099 / AstrBot 6185+6199 / mcp-v2 8765+8766 /
  工作台 7911–7913 / 核心（临时，`core-link.json` 里读）。

## 7. 教它之前先会的四条排障

1. **读不到模型** → 看工作台实例是否在跑、Arena 标签页是否开着；再点桌面端「扫一遍实例」，
   看 `runtime\arena\rooms.json` 的 `at` 有没有变新。
2. **派发说不唯一** → 正常，回去看左侧栏备注，让主人指一条；不要按编号猜。
3. **403** → 拿错令牌（插件令牌打了 GUI 路由），换界面令牌。令牌永远不要贴到聊天里。
4. **窗口没了 / 托盘还在** → 大概率勾了「隐藏任务栏图标（只留托盘）」，托盘右键取消即可。

## 8. 一句话总结

Arena 负责「看谁在跑、往哪条会话说话」，MCP 负责「动手干活」；
两边的共同底线是：**先读、读不到就停、唯一才动、重启要授权**。
