## 一、最终效果（实测）

| 阶段 | QQ 端可见延迟 |
|---|---|
| 修复前 | **12–13 秒/条**，且偶发「5 分钟不回」「4 分钟不回」 |
| 第一轮后（静默窗 + provider） | 12–13 s → 4–6 s（但每次唤醒仍固定 +8 s） |
| 第二轮后（批量窗口 + 限流 + 观察窗口） | 常规 4–6 s，最坏 60 s（不再是 5 分钟） |
| 第三轮后（打断等待） | 观察中的消息**秒回**（等待被打断，4.1 s 内返回验证通过） |

实测样本：16:52:26→30（4s）、16:53:33→37（4s）、17:05:05→10（5s）、17:05:49→53（4s）、17:10:27→33（6s）。

## 二、找到并修掉的真因（全部有文件+行号/日志时间戳）

### 配置类（只改 config.json，结构比对过：24 键一致、差异只有下列项、密钥未变）
| 项 | 原值 | 新值 | 根因 |
|---|---|---|---|
| `socialV2.wait.minQuietAfterNewMs` | 10000 | **2500** | 静默窗是硬下限（`quietMs = max(下限, 模型传值)`），模型传 0 也被抬到 10 秒 —— bridge.js L7433-7440 |
| `socialV2.wait.defaultQuietMs` | 8000 | **2500** | 同上，默认建议值又把它抬高 |
| `socialV2.wait.batchWindowMs` | 8000 | **2000** | 每次唤醒先排 8 秒批量窗口 —— bridge.js L12420-12429 |
| `socialV2.wake.maxWakePerMinute` | 1 | **4** | 命中限流不是丢弃而是延后重试，最多压 60 秒 —— bridge.js L12176-12206 |
| `socialV2.wake.maxWakePerHour` | 12 | **40** | 按小时命中会压一整小时 |
| `socialV2.wake.preSleepWaitMs` | 300000 | **60000** | 模型按提示做 5 分钟「沉睡前观察」，窗口内的消息不回（实测 17:06:12 → 17:10:30） |
| `socialV2.wait.maxMs` | 600000 | **120000** | 任何长轮询的上限 |
| `dsh.provider` | deepseek-account | **deepseek-official** | DSH 模型目录里**没有** deepseek-account（`routableProviders` 只有 deepseek-official / deepseek-modlens），每轮 selectModel 必然失败两次 |

### 代码类（src/bridge.js，回滚点：`docs/runs/20261026-perf-fix/bridge.js.bak-20261026-waitabort`）
| 改动 | 说明 |
|---|---|
| 新增 `activeWaitAborts` | 按归一后的会话 key 记录正在进行的等待的打断器 |
| `/api/socialV2/wait` 登记打断器 | `abortWait` 只翻标志位；reply 静默等待 / 新消息等待 / 到达后的静默窗三处循环都加了 `!waitInterrupted` 判断 |
| 打断时也交出消息 | `newMessages` 带 `arrived \|\| waitInterrupted`，并补 `arrived=true`（否则模型把 `timeout=true` 读成「没人说话」）；响应新增 `interrupted` / `interruptedReason` |
| `scheduleWakeV2` 触发打断 | `private/atMention/nameMention/question/poke/ownerRelay` —— 对方直接开口时先结束观察等待 |
| 手动唤醒触发打断 | 操作者明确唤醒，就不该被模型自己的长轮询拖着 |
| `armPendingWakeLease` 30 → 5 分钟 | 漏一个 turn/end 原来会静默 30 分钟；缩短 + 到期打日志 |

**确定性验证**：控制台令牌起一个 `timeoutMs=60000` 的等待 → 4 秒后调用 `/api/socialV2/wake` → 等待在 **4105 ms** 返回，响应含 `"interrupted": true, "interruptedReason": "manualWake"`；bridge.log 出现「打断观察等待 private:<OWNER_QQ>（原因=manualWake）」✓。
`node --check` 通过（每次改动后都做；不通过会自动回滚备份）。

### DSH 本体（第三方程序）
- **BigInt bug 定位到源码行**：`app.asar` 内 `@deepseek-ai/dsh-fs-local/lib/index.js` **L243/L258 `mode: Number(info.mode & 511n)`** —— asar 内路径下 Electron 垫片返回普通 Stats，与 BigInt 字面量按位与即抛 `Cannot mix BigInt and other types`（L270 包成 FsError）→ skill provider 整个被跳过 → 用户自己的 skills 也加载不出来。累计刷屏 **10991 条**。
- **上游未修**：已下载 npm 上更新的 `@deepseek-ai/dsh-fs-local@0.2.1-rc.3` 逐行比对，文件与本机**字节一致**（41311 B），那行原样还在 → 升级无用，只能绕行（已把 `bundledSkillDir` 指到 asar 外 + `restart-dsh.ps1` 设 `DSH_BUNDLED_SKILL_DIR`）。
- **第三方插件逐个核对端点**：`@liustack/modlens` 是模型 provider（私聊若被切过去走第三方端点，桥接已强制 deepseek-official）、`@liustack/modsearch` 是搜索 provider、`open-sea-skin` 版本过时等于没装、`dsh-switchman` 缺 /compact。审计时 DSH 对外连接全为 127.0.0.1。
- **纠正上一轮误报**：harness.log 里的「401/429」是时间戳数字被误匹配，日志里没有真实鉴权失败或限流。

## 三、还没做的（要你点头）

1. **群聊也支持打断**：目前只有私聊/@/点名类原因会打断观察等待，群里的普通消息不会（避免群消息频繁打断观察）。要放开可以改一行。
2. **`open-sea-skin` 从 profile 依赖里摘掉** —— 它现在等于没装，只留一条无害 warning；摘它要动 profile 的依赖树，收益小、风险不小。
3. **给上游提 issue**：`dsh-fs-local` 的 asar BigInt bug（附上 L243 的最小复现），这是唯一能根治技能插件刷屏的办法。
4. **DSH 桌面版比上游落后一个 rc**（本机 0.12.1 / harness rc.2，上游 rc.3 已于 10-23 发布）—— 但 rc.3 没修那个 bug，升级收益有限、风险不小，暂不建议动。
5. **DSH 那个会话没有 /compact** → 上下文只增不减：你 DSH 界面里那个会话会越聊越慢，重开一个会话即可；也可以给它的 preset 补上 compaction。
