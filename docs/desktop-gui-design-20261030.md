# 大肥鱼桌面端 · 最终设计方案

> 日期：2026-10-30
> 状态：已确认，实现中（阶段 0 起，2026-10-30；接手自 opencode 会话 playful-eagle）
> 目标：把整个大肥鱼项目收进一个 Windows 桌面软件
> 原则：一个图标、一个窗口、后台自动带起全部服务；日常不需要浏览器、终端或任何后台面板

---

## 一、最终产品定义

### 1.1 用户看到的东西

只有一个软件：**大肥鱼**。

- 桌面一个图标，开始菜单一个入口，托盘一个常驻图标。
- 打开只有一个主窗口。
- QQ 扫码登录、聊天、群管理、人格、记忆、日志、备份、Arena 工具调用都在这个窗口里。
- 后台服务由软件自己启动、检查、重启和关闭，用户不需要单独打开任何东西。
- 出错时只说人话，例如“QQ 连接断开，正在重连”，不把内部服务名、端口、堆栈直接丢给用户。

### 1.2 界面里不会出现

- 不出现 AstrBot、NapCat、OneBot、WebUI、Dashboard、MCP 等内部名词。
- 不出现 6185、6099、6199、8790 等端口，除非用户主动打开“诊断信息”。
- 不要求用户开浏览器、开终端、复制 token、改 JSON。
- 不要求用户保存 QQ 密码。

### 1.3 不做什么

- 不重写 QQ 协议，不替代官方 QQ。
- 不把现有机器人引擎推倒重写。桌面端是“外壳 + 本地控制核心”，底层继续复用已经跑通的生产能力。
- 不把服务直接塞进 GUI 进程里；服务隔离，崩溃可恢复。
- 第一版不做公网访问，不做局域网开放，不把 Arena 控制面暴露到任何非本机地址。
- 第一版不追求“单文件 EXE 把所有东西塞进一个进程”；最终交付是安装包 + 一个桌面入口，运行时仍在后台分进程，但用户无感。

## 二、整体体验

### 2.1 首次启动

1. 双击“大肥鱼”。
2. 欢迎页：检测本机环境、QQ、数据目录。
3. 选择数据方式：
   - **接管现有数据（推荐）**：识别当前生产数据，原样接管，不迁移、不覆盖。
   - **全新开始**：使用新的数据目录，不动旧数据。
4. 进入登录页，用手机 QQ 扫码。
5. 登录成功后自动同步群、会话、人格、模型和 Arena 状态。
6. 进入主界面，托盘常驻。

### 2.2 主界面布局

默认窗口 1200 × 800，最小 960 × 640。

```text
┌──────────────────────────────────────────────────────────────┐
│ 大肥鱼        ● QQ在线  ● 服务正常  ● 模型可用  ● Arena就绪  │
├────────┬──────────────────┬──────────────────────────────────┤
│ 首页   │ 会话列表          │ 聊天 / 详情                       │
│ 消息   │ 私聊              │                                  │
│ 群组   │ 群聊              │  消息气泡                         │
│ Arena  │                  │  工具调用卡片（可折叠）            │
│ 人格   │                  │                                  │
│ 记忆   │                  │                                  │
│ 日志   │                  │                                  │
│ 备份   │                  │  ┌────────────────────────────┐  │
│ 设置   │                  │  │ 输入框              [发送] │  │
└────────┴──────────────────┴──────────────────────────────────┘
```

- 左侧导航固定，不堆功能。
- 聊天页三栏；其他页面两栏或单页。
- 顶部状态条常驻，点击可展开详情。
- 关闭窗口默认最小化到托盘，第一次会提示；托盘右键可退出。
- 支持浅色/深色，跟随系统，也可手动切换。

### 2.3 托盘菜单

- 打开大肥鱼
- 暂停回复 / 恢复回复
- 重启服务
- 立即备份
- 退出

托盘图标用状态点表示：绿色在线、黄色重连、红色故障。

### 2.4 通知

只在真正需要用户处理时弹通知：

- QQ 掉线，需要重新扫码
- 服务连续重启失败
- 新未读消息（可关闭）
- Arena 任务完成/失败
- 备份失败

普通消息不刷屏。

## 三、页面设计

### 3.1 首页

不是功能堆砌页，只回答三个问题：现在好不好、最近发生了什么、下一步能做什么。

- 主状态卡：头像、昵称、QQ 号、“在线 / 重连中 / 未登录”、运行时长。
- 四个状态块：
  - QQ 连接
  - 消息服务
  - 模型
  - Arena
- 快捷操作：
  - 扫码登录 / 重新登录
  - 暂停回复
  - 立即备份
  - 打开 Arena
- 最近会话 3 条，点击直接进聊天。
- 今日摘要：收到消息数、发出消息数、Arena 任务数、错误数。

### 3.2 消息

- 只显示已授权的会话：主人私聊 + 已启用群。
- 每个会话显示：头像、名称、最后一条、时间、未读数、暂停/睡眠状态。
- 聊天窗口：
  - 左右气泡，自己/大肥鱼的消息有明确标识。
  - 支持文本、图片、表情；第一版先做文本 + 图片，语音/文件后续补。
  - 引用回复、复制、重发、定位到未读。
  - 输入框支持多行、粘贴图片、发送前预览。
  - 发送身份固定为“大肥鱼”，不伪装成主人。
- 工具调用卡片：
  - 出现在触发它的消息下方，默认折叠。
  - 显示：工具名、参数摘要、耗时、成功/失败、结果摘要。
  - 例如：“查询记忆 · dfy_memory_search · 12ms · 成功”。
  - 不显示模型思维链，不显示内部 prompt。
  - Arena 派活卡片可直接跳到任务详情。
- 会话状态：
  - “回复中”显示轻量动画。
  - “已暂停”“睡眠到某时间”在标题旁显示。
  - 断线时顶部显示黄色条，不阻塞看历史。
- 消息只保留一份事实源，GUI 不另造聊天数据库。

### 3.3 群组

- 已启用群卡片：群名、群号、成员数、未读数、最后活跃时间、回复开关。
- “启用新群”：
  - 从 QQ 群列表选择。
  - 显示将发生的变更：加入回复白名单、同步群资料。
  - 二次确认后原子写入两层配置，先备份，再重启/热加载。
- “停用群”：
  - 二次确认，说明会停止回复但保留历史。
  - 不删除数据。
- 群详情：
  - 群资料、群事实、成员概览。
  - 权限说明：群友能查什么、不能查什么。
  - 旧群默认不在列表里；只有主动打开“显示未启用群组”才出现。
- 不提供“批量拉群”“自动加群”等高风险功能。

### 3.4 人格与模型

- 人格编辑：
  - 系统人格正文。
  - 说话风格、边界、禁忌、示例对话。
  - 版本历史：查看、对比、恢复。
  - “试聊”沙盒：不连接 QQ，只在本机测试回复风格。
- 模型设置：
  - 当前模型、备用模型、温度、上下文长度、流式开关。
  - Provider 列表、API Key（只显示掩码）、连接测试。
  - 保存前自动备份；保存后明确提示“下一条消息生效”或“需要重启服务”。
- 不把底层配置文件的字段直接暴露成表单；只暴露产品需要的选项。

### 3.5 记忆

- 搜索：按关键词搜最近消息、长期记忆、人物、表情包、黑话。
- 分类：
  - 最近记忆
  - 人物档案
  - 群事实
  - 表情包
  - 黑话
- 每条显示来源、时间、隐私级别。
- 第一版默认只读；后续支持编辑/删除，删除进回收站，需二次确认并自动备份。
- 旧群数据继续过滤，不在界面出现。

### 3.6 日志

- 实时滚动，支持暂停。
- 筛选：全部 / 聊天 / 工具 / Arena / 错误。
- 搜索、复制、清屏、导出诊断包。
- 默认只显示人话摘要；展开才看技术细节。
- 自动脱敏：token、Cookie、API Key、二维码内容、MCP 地址、密码字段一律不进入日志和诊断包。
- 诊断包内容：版本、运行状态、脱敏日志、配置摘要、最近错误；不含聊天正文和密钥。

### 3.7 备份

- 快照列表：时间、原因（手动/改配置/升级前）、大小、包含项、校验状态。
- 操作：立即备份、恢复、导出、删除。
- 自动备份时机：
  - 修改人格/模型/白名单
  - 升级前
  - 恢复前
- 恢复流程：
  1. 校验快照哈希。
  2. 停止相关服务。
  3. 再备份当前状态。
  4. 恢复文件。
  5. 启动并做健康检查。
  6. 失败自动回滚。
- 新备份默认加密，密钥用 Windows DPAPI 保护；导出时可另设密码。
- 现有明文备份目录保留，首次运行只索引，不擅自改写。

### 3.8 设置

- 常规：开机自启（默认关）、关闭到托盘、通知、主题、语言。
- 数据：数据目录、备份目录、磁盘占用、清理。
- 安全：Arena 高风险工具开关、命令执行授权、日志脱敏级别。
- 更新：检查更新、更新通道、版本号。
- 诊断：服务状态、端口、日志目录、导出诊断包。
- 危险区：退出登录、重置本地设置、彻底删除数据（单独确认）。

## 四、扫码登录设计

### 4.1 原则

- 只做扫码登录，不收集、不保存 QQ 密码。
- 二维码只在内存中显示，不写日志、不落盘、不进截图缓存。
- 登录状态由本机 QQ 接入层提供，GUI 只做展示和操作。
- 登录成功后自动恢复会话；登录失效时保留历史，提示重新扫码。

### 4.2 登录状态机

```text
启动
  ↓
检查是否已登录
  ├─ 已登录 → 在线
  └─ 未登录 → 获取二维码
                 ↓
              等待扫码
                 ↓
              已扫码，等待手机确认
                 ↓
              登录成功，正在同步
                 ↓
              在线
```

异常分支：

- 二维码过期 → 自动刷新，显示倒计时。
- 扫码后取消 → 回到等待扫码。
- 新设备验证 → 提示“请在手机 QQ 上确认本次登录”，不伪造密码框。
- 网络异常 → 显示重试，不反复弹窗。
- 账号被限制 → 显示原因和建议，不循环重试。

### 4.3 登录页

```text
┌─────────────────────────────────────┐
│  登录大肥鱼                          │
│                                     │
│        ┌───────────────┐            │
│        │               │            │
│        │   二维码      │            │
│        │               │            │
│        └───────────────┘            │
│                                     │
│  请用手机 QQ 扫码                    │
│  二维码 58 秒后自动刷新   [立即刷新] │
│                                     │
│  [使用上次账号快速登录]              │
│  [切换账号]                          │
└─────────────────────────────────────┘
```

- 二维码区域 220 × 220，带倒计时环。
- 状态文字必须明确：获取中、等待扫码、已扫码待确认、登录成功、已过期、失败。
- “快速登录”只在 QQ 本机保留过该账号时出现；点击后仍需手机确认。
- “切换账号”先退出当前账号，二次确认，不影响历史数据。
- 登录成功后不弹“成功”大对话框，直接淡入主界面。

### 4.4 掉线与重登

- 顶部状态条变黄：“QQ 已断开，正在重连”。
- 自动重连 3 次；仍失败则托盘通知 + 登录页入口。
- 重连期间可以看历史、改配置、看日志，但不能发送。
- 重新扫码成功后，未读和会话状态继续保留。

### 4.5 内部接口

登录适配层读取本机 QQ 接入层的本地 WebUI 凭据，调用其登录接口。界面不接触这些接口。

已核对的可用能力：

- `GetQQLoginQrcode`：获取二维码
- `CheckLoginStatus`：登录状态/阶段
- `RefreshQRcode`：刷新二维码
- `GetQuickLoginList` / `GetQuickLoginListNew`：本机快速登录账号
- `SetQuickLogin`：设置快速登录
- 登录成功后由 OneBot 连接状态确认“真正可收发”

实现时由本地核心统一封装，GUI 只调用：

- `login.status`
- `login.qrcode`
- `login.refresh`
- `login.quick`
- `login.logout`

## 五、Arena 工具调用设计

### 5.1 现状

当前生产插件只有 15 个社交类工具，Arena 的 7 个工具没有接进生产。旧控制面仍有以下能力，但监听在固定端口且没有 token、Origin 校验，不能原样恢复：

- `arena_dispatch`：派活到队列
- `arena_tasks`：待办任务
- `arena_models`：模型目录 + 主人备注
- `arena_set_model_note`：写模型备注
- `arena_exec`：在本机执行一条命令
- `workbench_status`：工作台状态
- `workbench_action`：打开/关闭工作台实例

旧控制面还支持：

- 浏览器派活、路由预览、等待结果
- 任务历史、任务结果回写
- 工作台模型备注
- 审计日志

### 5.2 改造原则

- 不再固定监听 8790。
- 改成桌面端内部网关：随机本机端口 + 每次启动随机 token + 只允许桌面核心调用。
- 网关的 MCP 地址、token、Cookie 不进入 GUI、不进入日志、不进入聊天。
- 高风险工具默认关闭，必须由主人在 GUI 里显式授权。
- 群聊和陌生人不能调用派活、执行命令、开关工作台。
- 所有调用写审计：谁、何时、什么工具、参数摘要、结果、耗时。

### 5.3 Arena 页面

顶部四个标签：**任务 / 模型 / 工具 / 工作台**。

#### 任务

```text
┌ 新任务 ─────────────────────────────────────┐
│ 要做什么  [______________________________]  │
│ 模型      [自动 / 按备注选择        ▼]     │
│ 备注      [验收标准、偏好、避免什么...]     │
│ 方式      (•) 队列派活   ( ) 浏览器会话     │
│                              [派活]         │
└─────────────────────────────────────────────┘

进行中 2
#A102  修复登录页错位        运行中   08:21
#A101  整理群文件            等待中   03:12

已完成
#A100  检查备份完整性        成功     昨天
```

- 默认“队列派活”，稳定、可追踪。
- “浏览器会话”是高级模式，依赖 Arena 页面和已运行的工作台实例；不可用时直接禁用并说明原因，不静默失败。
- 任务状态：排队、运行中、等待确认、成功、失败、阻塞、取消。
- 任务详情：目标、模型、备注、时间线、结果、错误、关联聊天消息。
- 支持复制结果、在聊天中打开、重新派活。
- 轮询有上限，避免刷接口；页面关闭后后台仍可查询。

#### 模型

- 模型卡片：名称、ID、能力标签、主人备注、最近使用。
- 备注是路由依据：保存后立即生效，旧任务不受影响。
- “路由预览”：显示当前备注会匹配到哪个 Arena 会话；匹配不到、重复、模糊时明确报错，绝不猜。
- 不把“模型 ID”硬编码成产品逻辑；以主人备注为准。

#### 工具

工具清单 + 权限 + 最近调用：

| 工具 | 默认权限 | 说明 |
|---|---|---|
| 查看模型/任务/工作台 | 允许 | 只读 |
| 派活、写模型备注 | 主人确认 | 写操作 |
| 浏览器派活 | 主人确认 | 依赖工作台 |
| 执行命令 | 默认关闭 | 高风险，限时授权 |
| 开关工作台 | 主人确认 | 影响本机 |

- “工具测试台”只对安全工具开放；发送消息、执行命令必须二次确认。
- 测试台显示请求参数和返回结果，默认脱敏。
- 高风险开关打开后有时限（例如 10 分钟），到点自动关闭；关闭后所有执行请求拒绝。
- 群聊里即使模型想调用，也会被权限层拒绝，并返回“此操作仅主人私聊可用”。

#### 工作台

- 实例列表：名称、登录状态、运行状态、PID、模型备注。
- 操作：打开、关闭、刷新状态。
- 当前只检查 `profile_3` 这一条浏览器通道，和现有约定一致；不擅自检查或开关其他实例。
- 关闭实例前二次确认，说明可能中断正在进行的浏览器任务。

### 5.4 聊天里的 Arena 工具

生产插件新增 7 个工具，名字统一加 `dfy_` 前缀，避免和现有工具冲突：

- `dfy_arena_dispatch`
- `dfy_arena_tasks`
- `dfy_arena_models`
- `dfy_arena_set_model_note`
- `dfy_arena_exec`
- `dfy_workbench_status`
- `dfy_workbench_action`

权限：

- 只有主人私聊可用。
- 群聊、非主人一律拒绝。
- `dfy_arena_exec` 默认不可用；主人在 GUI 里临时授权后才可用。
- 每次调用都进工具轨迹和审计日志。

工具调用轨迹示例：

```text
她 → dfy_arena_models        成功  18ms
她 → dfy_arena_dispatch      成功  42ms
     任务 #A103 已排队
她 → dfy_arena_tasks         成功  21ms
     1 个进行中
```

### 5.5 两种派活方式

- **队列派活**：写入 Arena MCP 任务队列，适合稳定后台执行。
- **浏览器派活**：在已运行的 Arena 会话里发送，依赖浏览器工作台和左侧会话备注精确匹配。

GUI 必须明确显示当前用的是哪一种，不能把队列派活说成浏览器派活。

## 六、技术架构

### 6.1 技术选型

- 桌面壳：**Electron 44 + React + TypeScript + Vite**（改判，理由见下）
- UI：手写 CSS + 深浅色跟随系统；聊天列表虚拟滚动在阶段 2 引入（未引入 Tailwind，省一次依赖与体积）
- 本地核心：**Python 3.12 标准库**（`http.server` + `urllib`，零 pip 依赖）
- 进程管理：Electron 主进程 supervisor（`src/main/supervisor.mjs`）
- 通信：本地 HTTP + SSE；界面不直接连本地核心，一律经 preload 的 IPC 由主进程代理
- 打包：NSIS 安装包（`electron-builder`，推迟到阶段 4 安装）

**6.1.1 为什么从 Tauri 改成 Electron（2026-10-30 实测）**

本机没有任何 C++ 工具链：`rustc`/`cargo`/`vswhere`/`cl.exe`/Windows Kits/mingw 全部缺失。
装齐 Tauri 前置需要下载 MSVC + Windows SDK 约 1.5–2.5 GB，而实测出口带宽约 **0.27 MB/s**
（rustup-init 15 秒只拿到 4.1 MB；`aka.ms` 的 Build Tools 引导程序 19 秒连跳转都没完成），
预计单项就要 1.5–2.5 小时，还不含 400–600 个 crate 与首次编译。
与此同时 `electron-v44.7.0-win32-x64.zip`（151 MB）**已在本机缓存**，零下载。
因此按「30 分钟内起不来就回退」的约定改用 Electron。WebView2 运行时（156.0.4314.50）其实已具备，
被卡的只有编译工具链；若日后补上 Rust + MSVC，可按本文档原选型迁回 Tauri，
除 6.1/6.2/8.1 外其余章节（体验、扫码状态机、Arena 网关、安全、阶段划分、验收标准）均与选型无关。

原方案（保留备查，当时未计入工具链缺失）：Tauri 2 + React + TS + Vite，理由是安装包与内存占用更小、
Windows 原生 WebView2 的托盘/通知/自启成熟、Rust 侧适合做进程监管与本地凭据管理。
代价：安装包约 15 MB → 约 90 MB；主进程由 Node 承担原 Rust supervisor 的职责，
DPAPI 凭据保护改由主进程调用 PowerShell 完成（阶段 3）。详见 `desktop/docs/TOOLCHAIN_DECISION.md`。

### 6.2 进程拓扑

```text
大肥鱼.exe（Tauri）
├─ UI（React）
├─ Supervisor（Rust）
│  ├─ 启动/停止/重启/健康检查
│  ├─ 单实例锁、托盘、通知、更新
│  └─ 持有本地核心 token，不暴露给 WebView
│
├─ dfy-core（Python，本地核心）
│  ├─ 聚合状态、会话、消息、群、人格、备份
│  ├─ 扫码登录适配
│  ├─ Arena 受控网关
│  └─ 事件总线 / 审计 / 脱敏
│
├─ 机器人引擎（后台，隐藏）
│  └─ 本地面板桥接插件：状态、发送、已读、工具轨迹
│
├─ QQ 接入层（后台，隐藏）
│  └─ 本机 WebUI + OneBot，仅 loopback
│
└─ 官方 QQ NT
```

用户只看见“大肥鱼.exe”。其余进程没有窗口、没有桌面图标、没有开始菜单入口。

### 6.3 启动顺序

1. 获取单实例锁。
2. 启动本地核心，分配随机端口和本次启动 token。
3. 启动 QQ 接入层，等待本机 WebUI 就绪。
4. 启动机器人引擎，等待 OneBot 连接建立。
5. 等待桥接插件注册。
6. 检查登录状态；未登录则 UI 进入扫码页。
7. 状态全部就绪后，主界面可交互。

任何一步失败：

- 显示人话错误。
- 自动重试，带退避和冷却。
- 连续失败才通知用户。
- 不弹一堆技术日志。

### 6.4 通信与鉴权

- 所有本地服务只绑定 `127.0.0.1`。
- 本地核心端口随机，不固定。
- 每次启动生成 256 位随机 token，通过管道传给核心，不写命令行、不写日志。
- WebView 不接触 token；所有请求走 Tauri IPC，由 Rust 代理。
- 核心校验 `Origin`/`Host`，拒绝非本机来源。
- 服务间调用使用独立 token，不共用。
- 旧 8790 不再监听；旧 MCP 入口如果需要保留，只能指向新网关。

### 6.5 数据流

**收消息：**

```text
QQ → QQ 接入层 → 机器人引擎 → 桥接插件
   → 本地核心事件总线 → Rust → UI
```

**发消息：**

```text
UI → Rust → 本地核心 → 桥接插件 → 机器人引擎 → QQ
```

发送成功后由插件记录出站，再回推 UI；UI 先做乐观更新，失败则标红可重试。

**工具调用：**

```text
插件工具包装器 → 记录工具名/参数摘要/耗时/结果
             → 本地核心 → UI 工具卡片
```

只记录工具元数据，不记录模型思维链。

**扫码：**

```text
UI → Rust → 本地核心 → QQ 接入层 WebUI
   ← 二维码/状态 ←
```

二维码只在内存中传递，不落盘。

**Arena：**

```text
UI / 聊天工具 → 本地核心 → Arena 网关 → MCP 队列 / 浏览器工作台
```

### 6.6 数据归属

- 聊天记录、未读、暂停状态：现有插件状态文件，事实源不变。
- 长期记忆、人物、表情包、黑话：现有数据和只读层，事实源不变。
- 人格、模型、白名单：现有配置，核心通过适配器读写。
- Arena 任务、模型备注、审计：现有 `ops-dfy` 数据，迁移到应用数据目录时保留原路径兼容。
- GUI 自己的设置、窗口状态、更新记录：应用数据目录。
- 不另建一套聊天数据库，避免双写和不同步。

## 七、安全设计

### 7.1 网络

- 所有服务只监听 loopback。
- 不开放局域网，不做端口转发，不默认开启远程访问。
- Windows 防火墙不为这些端口放行入站。
- 诊断页可一键检查“是否存在非 loopback 监听”。

### 7.2 凭据

- QQ 只扫码，不保存密码。
- API Key、WebUI token、Arena 凭据用 Windows DPAPI 保护。
- 日志、诊断包、错误弹窗自动脱敏。
- 二维码不写日志、不落盘、不进入备份。
- 备份默认加密；导出可另设密码。

### 7.3 权限

- 主人私聊：日常聊天 + 安全工具。
- 群聊：只允许社交类工具；Arena 派活/执行/工作台一律拒绝。
- `arena_exec`：默认关闭，限时授权，逐条确认，审计。
- 工作台开关：二次确认。
- 修改白名单/人格/模型：二次确认 + 自动备份。
- 所有高风险操作有“谁在什么时候做了什么”的审计记录。

### 7.4 供应链与更新

- 依赖锁定版本，安装包记录哈希。
- 更新包签名校验；校验失败拒绝安装。
- 更新前自动备份，更新后健康检查，失败自动回滚。
- 机器人引擎版本固定，升级前跑桥接兼容测试。

## 八、安装、更新与回滚

### 8.1 安装包

- 名称：`大肥鱼-Setup-x.y.z.exe`
- 按用户安装，默认目录 `%LOCALAPPDATA%\Dafeiyu`。
- 创建桌面快捷方式、开始菜单入口、可选开机自启。
- 首次启动向导：环境检查 → 数据方式 → 扫码 → 模型 → 完成。
- 官方 QQ NT 是外部依赖：检测不到时给出官方下载入口，不捆绑来路不明的 QQ。

### 8.2 两种安装模式

- **完整版（默认）**：内置 Python/Node 运行时和后台服务，用户不需要装开发环境。
- **轻量版**：接管本机已有的机器人引擎和 QQ 接入层，体积小，适合当前这台已经跑通的机器。

首次启动自动检测；检测到现有生产数据时，默认推荐“接管”，并先做只读盘点。

### 8.3 更新

- 应用内检查更新，显示版本说明。
- 下载 → 验签 → 备份 → 安装 → 启动 → 健康检查。
- 健康检查失败自动回到旧版本。
- 不静默升级后台服务；涉及数据迁移时先提示。

### 8.4 卸载

- 默认保留用户数据，只删程序。
- “彻底删除”单独入口，二次确认，明确列出将删除的目录。
- 卸载前可选导出备份。

## 十、验收标准

1. 双击桌面图标，不打开浏览器、不打开终端，主窗口可用。
2. 后台服务自动启动；杀掉任一服务，能自动恢复并在 UI 反映。
3. 未登录时显示二维码；扫码、手机确认、登录成功全流程在窗口内完成。
4. 二维码过期能自动刷新；断线能提示并重新登录。
5. 私聊和两个已启用群能看消息、收未读、发送、已读；未授权会话不出现。
6. 工具调用在聊天里可见，但不泄露思维链和密钥。
7. Arena 能派活、看状态、看结果、写模型备注、看工作台状态。
8. 非主人/群聊调用 Arena 高风险工具被拒绝。
9. `arena_exec` 默认关闭；授权有时限；所有执行有审计。
10. 修改人格/模型/白名单自动备份；恢复失败能回滚。
11. 日志和诊断包不含 token、Cookie、API Key、二维码、MCP 地址。
12. 所有服务只监听 `127.0.0.1`；不存在未鉴权的固定控制端口。
13. 关闭窗口进托盘；托盘能暂停、重启、备份、退出。
14. 安装、升级、卸载不丢数据；升级失败能回滚。

真实 QQ 的私聊/群聊验收按用户要求暂缓；先用本机伪事件/沙盒验证，等用户开口再做真机验收。

## 十一、已知风险与处理

| 风险 | 处理 |
|---|---|
| QQ 新设备验证/风控 | 只做官方扫码和手机确认，不绕过；给出明确提示 |
| 机器人引擎升级导致插件不兼容 | 固定版本；升级前跑桥接回归；失败回滚 |
| 浏览器派活依赖 Arena 页面和工作台 | 默认队列派活；浏览器模式显式标注依赖，不可用就禁用 |
| 安装包体积大 | 完整版内置运行时；轻量版接管现有安装 |
| Windows Defender 误报 | 代码签名；安装包哈希；不打包可疑二进制 |
| 本地端口被其他程序访问 | 随机端口 + 每次启动 token + 只允许 Rust 代理；旧固定端口关闭 |
| 备份含敏感配置 | 默认加密；DPAPI 保护密钥；导出可另设密码 |
| 误删数据 | 删除进回收站/先备份；恢复前再备份当前状态 |

## 十四、结论

这个方案的核心不是“给现有系统套一个控制台”，而是：

- 用户只面对一个“大肥鱼”桌面软件。
- 扫码、聊天、群、人格、记忆、日志、备份、Arena 全部在一个窗口里。
- 后台服务被 supervisor 管起来，用户不需要知道它们存在。
- Arena 从“未接入生产 + 无鉴权固定端口”改成“受控网关 + 7 个工具 + 权限/审计 + GUI 任务台”。
- 现有数据、白名单、生产配置不动；先接管，再逐步替换入口。
- 每一步可备份、可回滚，不拿生产做一次性大爆炸改造。

确认这个方向后，从阶段 0 开始，不直接改生产。
