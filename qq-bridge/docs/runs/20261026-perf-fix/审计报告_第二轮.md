## 一、DSH 本体（第三方程序）审计

### 1.1 技能插件刷屏：已定位到 DSH 的确切一行代码（上游未修）

- 现象：`harness.log` 里 `skill-registry: skill provider "filesystem" skipped: FsError: cannot list "...app.asar\node_modules\@deepseek-ai\dsh-agent-preset\skills": Cannot mix BigInt and other types`，累计 **10991 条**（10-17 → 10-26）。
- 根因（读 app.asar 里的 DSH 源码得到）：`node_modules/@deepseek-ai/dsh-fs-local/lib/index.js`
  - L239 / L254：`stat(path, { bigint: true })` / `lstat(path, { bigint: true })`
  - **L243 / L258：`mode: Number(info.mode & 511n)`** ← 罪魁祸首
  - L270：`throw new FsError('cannot list "${displayPath}": ${errorMessage(error)}', 'FS_IO_ERROR', { cause: error })` ← 报错包装
  - 触发条件：路径在 **app.asar 内**时，Electron 的 asar 文件系统垫片返回普通 `Stats`（`info.mode` 是 Number），与 BigInt 字面量 `511n` 按位与 → `TypeError: Cannot mix BigInt and other types` → 整个 skill provider 被跳过 → 用户自己的 skills（`~/.dsh/skills`、`~/.agents/skills`）也一起加载不出来。
- **上游状态（已核实）**：本机 DSH Desktop **0.12.1**，harness 插件为 **0.2.1-rc.2**；npm 上已有 **0.2.1-rc.3（2026-10-23 发布）**。我下载 rc.3 的 tarball 逐行对比：`lib/index.js` **41311 字节，与本机完全一致**，`mode: Number(info.mode & 511n)` 原样还在 → **rc.3 没修** → 升级不能解决，只能绕行（已绕行）+ 值得给上游提 issue。
- 本轮处置：DSH profile 的 `cordis.patch.yml` 给 skill-filesystem 指定 asar 之外的 `bundledSkillDir`（`%USERPROFILE%\.dsh\skills-empty`）；`restart-dsh.ps1` 启动前设置 `DSH_BUNDLED_SKILL_DIR`（宿主组合实例用）。

## 五、遗留（本轮没动，需要你点头）

1. **消息到达时打断正在进行的观察等待** —— 现在最长仍会压 60 s；要做到"秒回"需要在 bridge.js 加 abort（当前没有任何打断等待的机制）。这是一处真实代码改动，等你确认再动。
2. **pendingWakeKey 泄漏** → 静默最长 30 分钟。建议把租约从 30 分钟降到 3–5 分钟并在到期时打日志（纯代码改动）。
3. **开机自启 + NapCat 看门狗** —— 现在机器重启后机器人不会自己起来；QQ 掉了也没人拉起（今天发生过一次，2.5 分钟消息进不来）。
4. **`open-sea-skin` 插件是死的**（版本对不上），可从 profile 依赖里摘掉，日志就不再报那条 warning。
5. **DSH 桌面版比上游落后一个 rc**（本机 0.12.1 / harness rc.2，上游 rc.3 已于 10-23 发布）——但 rc.3 **没有**修 BigInt 那个 bug，升级收益有限、风险不小，暂不建议动。
6. **`restart.bat` 别用**（会起双实例）；要重启桥接用「按 PID + 命令行匹配」的方式。
